# Session 100 - Keyframe Job Ownership Binding

Date: 2026-02-25

## Objective
- Close remaining high-value abuse risk: cross-tenant RunPod keyframe status probing by binding job IDs to authenticated user ownership.

## Changes Made

- `src/lib/server/requestTracking.js`
  - Added RunPod ownership helpers:
    - `registerRunpodJobOwnership({ uid, runpodId, routeKey, metadata })`
    - `hasRunpodJobOwnership({ uid, runpodId })`
  - Added user-scoped ownership record storage in Firestore:
    - `users/{uid}/runpod_jobs/{runpodId}`
  - Added TTL metadata for job ownership records.

- `src/routes/api/generate-keyframe/+server.js`
  - Registers RunPod job ownership after successful job submission.
  - Validates that RunPod response includes a non-empty job ID.

- `src/routes/api/generate-keyframe-status/+server.js`
  - Enforces ownership check before polling RunPod status.
  - Returns `404` when the requested job is not owned by the caller.

## Security Outcome

- Prevents authenticated users from polling statuses of other users' keyframe jobs by guessing/obtaining foreign `runpodId` values.
- Maintains per-user isolation for asynchronous generation workflows.
